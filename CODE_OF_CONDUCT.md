# Code of Conduct

## Our commitment

This project is developed in an academic context as part of a web and backend development practice.

The goal of this repository is to maintain a respectful, professional and collaborative environment while developing a task and project management application using ASP.NET Core Web API, Entity Framework Core and SQL Server.

Everyone interacting with this repository is expected to communicate respectfully and constructively.

---

## Expected behavior

Examples of positive behavior include:

- Using respectful and clear communication.
- Giving constructive feedback.
- Accepting different points of view.
- Focusing discussions on the project and its technical aspects.
- Helping improve the quality, maintainability and security of the code.
- Respecting the academic purpose of the repository.
- Explaining technical decisions clearly.
- Reporting issues in a useful and respectful way.
- Following the contribution guidelines defined in `CONTRIBUTING.md`.

---

## Unacceptable behavior

Examples of unacceptable behavior include:

- Insulting, offensive or disrespectful language.
- Harassment or personal attacks.
- Discrimination of any kind.
- Publishing private or sensitive information without permission.
- Introducing malicious code.
- Sharing credentials, secrets or private tokens.
- Requesting or exposing passwords, JWT secrets, API keys or database credentials.
- Plagiarism or misrepresentation of work.
- Disruptive behavior that negatively affects the project.
- Opening issues or pull requests with unrelated, spam or harmful content.
- Ignoring security and privacy guidelines intentionally.

---

## Academic integrity

This repository is part of an academic practice.

All work should respect the academic rules of the course or institution. The project should represent the author's own work and should properly acknowledge any relevant external resources, third-party libraries, documentation or examples used during development.

Unacceptable academic behavior includes:

- Copying code without understanding or proper attribution.
- Presenting someone else's work as original.
- Removing authorship or license notices from third-party code.
- Using external contributions in a way that violates academic rules.
- Hiding the use of external resources when they should be acknowledged.

---

## Security and privacy

Participants must not publish, request or expose sensitive information.

Sensitive information includes:

- Passwords
- Password hashes
- JWT secrets
- API keys
- Private tokens
- Database credentials
- Production connection strings
- Real user data
- Confidential academic or personal information

Security concerns should be reported privately following the instructions in `SECURITY.md`.

---

## Project communication

Communication around the project should remain clear, useful and respectful.

When discussing code, issues or pull requests:

- Focus on the technical problem, not the person.
- Explain the reason behind suggestions or requested changes.
- Be open to feedback.
- Avoid sarcasm, mockery or aggressive language.
- Ask for clarification when something is unclear.
- Keep discussions related to the project.

---

## Issues and pull requests

Issues and pull requests should be used responsibly.

Good issues should include:

- A clear title.
- A description of the problem or suggestion.
- Steps to reproduce the problem, if applicable.
- Expected behavior.
- Actual behavior.
- Screenshots, logs or examples if useful.

Good pull requests should include:

- A clear description of the change.
- The reason for the change.
- Any database migration added.
- Testing or verification steps.
- Notes about limitations or pending work.

Pull requests should follow the conventions described in `CONTRIBUTING.md`.

---

## Repository scope

This Code of Conduct applies to all project spaces, including:

- Repository content
- Issues
- Pull requests
- Discussions
- Documentation
- Commit messages
- Related communication channels

It also applies when representing the project in academic or technical contexts.

---

## Enforcement

The repository maintainer may take action when this Code of Conduct is not followed.

Possible actions include:

- Asking for clarification or correction.
- Editing or removing inappropriate comments.
- Closing issues or pull requests.
- Rejecting contributions.
- Restricting participation in the repository.
- Reporting serious academic or security concerns through the appropriate channels.

The purpose of enforcement is to keep the project respectful, safe and suitable for academic evaluation.

---

## Reporting concerns

If you notice behavior that violates this Code of Conduct, report it to the repository maintainer.

When reporting a concern, include:

- A description of what happened.
- Where it happened.
- Any relevant links, screenshots or context.
- Whether the issue also involves a security concern.

Security-related concerns should follow the process described in `SECURITY.md`.

---

## Maintainer responsibilities

The maintainer is responsible for:

- Keeping the repository organized.
- Reviewing contributions respectfully.
- Enforcing this Code of Conduct consistently.
- Protecting sensitive information.
- Maintaining the academic purpose of the project.
- Ensuring that accepted changes are aligned with the project scope.

---

## Final note

This project is intended to demonstrate backend development skills, including API design, database modeling, authentication, authorization, validation, logging and project documentation.

A respectful and organized development environment helps make the project easier to understand, maintain and evaluate.
